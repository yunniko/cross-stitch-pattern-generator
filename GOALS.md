### G-103 · The three workspaces are features: Generation, Edit and Export each switched with its tab — ACTIVE (accepted 2026-10-06)
- **What:** asked by the Owner, 2026-10-06. Generation, Edit and Export become features in the G-102 list, each one switch covering both the work and the way in: the workspace's tab and everything inside it. Hidden: the tab is absent and the workspace cannot be reached by any road (key, command list, link, a request to the server). Locked: the tab is shown greyed with its note. On, Locked or Hidden for the site, a person, a feature set, guests or accounts, as every other feature.
- **Why:** G-102 made the workspaces core (`feature: null`), so today a tier can withhold single generation settings or export kinds but not a whole stage; the Owner wants a stage as one switch.
- **Acceptance criteria (draft):** each of the three appears in `/admin/features` as one entry; Hidden and Locked hold for the tab, the keys and commands that open it, and the server routes behind it (generate, export), refused by name; the features inside a workspace keep their own switches, and a workspace switched off wins over them; with all On, the browser suite passes unchanged.
- **Constraints:** a chart already open keeps its data whatever is switched off (G-102's rule: never damage a chart). Admin pages are never exercised against the live site (standing rule).
- **Answered (Owner, 2026-10-06):** with Generation off, a person starts a chart as a new empty chart or by opening an existing one. When the workspace a person would land in is off, the next one that is on opens. When all three are off (not a normal state, possible in an emergency), a window says so with an error, instead of an empty editor.
- **Answered (Owner, 2026-10-06):** a control belongs to the workspace whose tab it is on: the photo settings and Crop on the Edit tab are Edit's; if they are also offered on the Generation tab, there they are Generation's.
- **Architecture fit (review, 2026-10-06):** the workspace list is the registry (`WORKSPACES` in `lib/editor/workspaces.ts`, D297). (1) Each workspace gains a `feature` declaration there and enters the feature list through `app/features/registry.ts` as every other registry does (D303); no workspace id is written into the admin page. (2) "A workspace switched off wins over the features inside": replaced in planning, see "Fixed in planning" (a) below. The review first asked for a parent relation in `lib/features/declare.ts` and `lib/features/resolve.ts`, which the Owner's second answer rules out. (3) The server's side is one mapping from a workspace to the requests behind it, read by `lib/features/request-check.ts` (Generation: jobs, colour recommendations, photo upload; Export: exports), not a check written into each route. (4) The places that assume Photo is always there go through one "first workspace that is on" rule in `lib/editor/workspaces.ts`: `workspaceShown`, `workspaceOpen`, `firstTools` (which throws when a workspace offers no tool), the starting value in `app/hooks/use-editor-view.ts`, and the `workspace` column of `REPLACE_PLANS` (`lib/editor/document-replace.ts`). (5) The three `view.workspace-*` commands (`app/commands/registry.ts`, `feature: null` today) name their workspace's feature. (6) Which workspace a control belongs to (the second answer above) follows from where its registry entry says it is offered, never from a list of control names in a panel component.
- **Answered (Owner, 2026-10-06, to the review's questions):** the tab keeps its name, Photo, and generating is its button. Read as: the feature is named Photo and covers the tab with everything on it, the Generate button and its commands (`generate.run`, `generate.cancel`) included, so "Generation" in this goal means Photo throughout. To confirm when planning: or is generating a switch of its own inside Photo, so that a set could show the tab and withhold the button? With Export off, Save in the bar and "Export, then start new" go off with it. With Photo off, the pixel-art start stays: it opens a picture as a chart in the browser and generates nothing.
- **Noted by the review:** "by link" has nothing to close today, since no address opens a workspace. With Export off nothing downloads the editable file, so a chart is kept only by the browser (and by the account, after G-108); the new-chart confirmation loses its one-press safe choice.
- **The acceptance restated (planning, 2026-10-06):** (1) `/admin/features` shows Photo, Edit and Export as three entries in a group of their own, each On, Locked or Hidden for the site, a person, a set, guests or accounts. (2) Hidden: the tab is absent, and no key, command, button, starting choice or dropped file opens the workspace or does its work; the server refuses its requests by name. Locked: the tab is greyed with its note, its commands are listed as unavailable with the same note, and the server refuses alike. (3) A feature inside a workspace keeps its own switch, and the workspace being off wins. (4) A person lands in the first workspace that is on; with all three off a window says so. (5) The chart in hand and the one the browser keeps are untouched by any switch. (6) With all three On the browser suite passes unchanged.
- **Fixed in planning (2026-10-06; each becomes a decision file when built):** (a) **The switch closes the workspace, not each feature inside it.** A control belongs to the workspace whose tab it is on (Owner), so one feature offered on two tabs would have two parents, and a feature's state shown to the admin would stop being its own. The three workspaces are therefore ordinary features (`workspace.photo`, `workspace.edit`, `workspace.export`; group "Workspaces"), and the ways in are closed in four places, each written once: the tab and the landing rule (`lib/editor/workspaces.ts`); the command assembly, where every command names the workspace it belongs to (`app/commands/registry.ts`: `generate.*` and `file.choose-photo` are Photo's, the export commands Export's, the tool commands Edit's); the tool in hand (`toolOffered` already goes by workspace); and the server's mapping from a request to its workspace. (b) **What is not a command goes through one:** the starting choices, a dropped photo, Save in the bar and "Export, then start new" call the same commands, so the refusal is not written a second time. (c) **The server's mapping** (`lib/features/request-check.ts`): `/api/jobs`, `/api/predictions` and `/api/photos` are Photo's, `/api/exports` is Export's; a job's later requests need a job, which Photo off never makes. The editable file, the palette file and pixel art are written in the browser and send no request, so for those three the browser's gate is the only one. (d) **Generate is part of Photo** and has no switch of its own (the reading recorded above, not yet confirmed). (e) **With Edit off,** Undo and Redo stay: they are on the bar in every workspace, and Undo also takes back a generation.
- **To confirm with the plan (Owner):** (d) and (e) above; the plan runs on them unless told otherwise.

### G-104 · A colour picker, held on a key without changing tools — ACTIVE (accepted 2026-10-06)
- **What:** asked by the Owner, 2026-10-06. A colour picker: pressing on a stitch takes its colour (and a backstitch line's) as the colour in hand. It is a tool of its own in the rail, and it is also reached by holding a modifier key with any drawing tool in hand: while the key is down the pointer picks, and on release the tool in hand is unchanged.
- **Why:** taking a colour from the chart today means finding it in the palette by eye.
- **Acceptance criteria (draft):** pick a stitch's colour with the tool and with the held key from Brush, Line, Rectangle, Oval and Fill; the tool in hand never changes; the pointer shows picking while the key is held; an empty cell picks the eraser (Owner, 2026-10-06; the draft first said it picks nothing); the picker is a feature in the G-102 list; unit tests on the key table, browser cases for both roads.
- **Constraints:** the key must not take one the Owner agreed in D288 or that a tool already uses as a modifier (Ctrl ends a backstitch line, D236; Shift takes larger steps for the keyboard cursor and Crop; Alt with Zoom zooms out). A tool is one module (D284).
- **Answered (Owner, 2026-10-06):** the held key is **Alt**. Known work: Alt alone moves focus to the browser menu on some systems, which must be suppressed while the chart has focus; Zoom's Alt (zoom out) stays, since the picker applies to the drawing tools.
- **Answered (Owner, 2026-10-06):** the picker takes the colour of the closest cell to the pointer ("get the closest cell"). Read as: the stitch in that cell, whole or half, is picked; a backstitch line over it is not (to confirm with the Owner when planning).
- **Architecture fit (review, 2026-10-06):** one tool module in `app/tools/`, listed in `TOOL_MODULES` (D284), its `feature` declared on its definition; its key and name reach the command list and the feature list from there. Three things the contracts lack today are added to the contracts, not worked around. (1) `EditorApi` (`app/tools/types.ts`) lets a tool read the colour in hand but not set it: it gains one call that takes a colour in hand, and the picker touches nothing else (D281). (2) A held command exists (`view.pan-held`, `keyOnly: "held"`), but `parseChord` (`lib/editor/commands.ts`) accepts a modifier only together with a key. The key grammar is extended to a modifier held alone, and `app/hooks/use-held-pan.ts` becomes one "tool held on a key" routine that Space's Pan and Alt's picker both declare; a second copy of that hook is not acceptable (one routine per job). Suppressing the browser's menu on Alt lives in that routine. (3) Which tools the held key applies to is a trait on the tool's definition, not a list of tool ids (whether the existing `shares: colours` serves or a new trait is needed is decided in planning: Select shares colours too). Zoom does not carry it, so its Alt is untouched.
- **Answered (Owner, 2026-10-06, to the review's questions):** picking an empty cell takes the eraser (the empty stitch, `EMPTY_CELL`), as any other colour is taken. The right button picks into the second colour square (`lib/editor/color-slots.ts`).
- **Settled (Owner, 2026-10-06, at acceptance):** with the pointer on a backstitch line, the line's thread is picked.
