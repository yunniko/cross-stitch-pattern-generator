# Exploratory QA, 2026-10-05 (G-094)

**Mode and scope:** scoped pass on what G-094 changed: undo and redo (now recorded changes on a document), the file (the
migration step, fabric in the chart, the server's writer of the editable file) and the autosave. Local production build with
the Rust engine, on the uncommitted G-094 work. A throwaway Playwright probe drove the interface and compared **saved files
byte for byte**, which is the strictest thing the app lets an outsider observe about a chart. Undo is meant to be unchanged
for the person, so the question was "is any chart different from what it would have been".

## Findings

| # | Severity | Finding | Outcome |
|---|---|---|---|
| 1 | wrong output (old) | The editable file inside "Export all" is written on the server by a second writer, which left out five things a chart can carry: the photo sliders, the dither pattern and its texture, Vivid, and the chosen colour set. A chart opened from a bundle had forgotten them. Found by reading the writer while adding fabric to it; shown by a test that failed before the fix | Fixed: the server's writer writes every field the editor's does, and a unit test and a browser case compare the two files byte for byte |
| 2 | wrong output (old, harmless) | The same chart saved before and after a reload gave two different files: the photo's record came back from the autosave with its keys in another order. Same content, different bytes | Fixed: the record is rebuilt in the order a fresh chart has. A unit test and a browser case pin it |
| 3 | document drift (old) | The brief gave the unit's default as inches; it is centimetres | Fixed in `03` and `08` |
| 4 | note | A file that says it is version 5 or later, has no brand, and still carries the pre-version-5 one-brand flag is no longer read as DMC: that flag is now handled where files older than 5 are brought up to date. No version of the app wrote such a file | Left as it is |
| 5 | note | `app/workspace.tsx` is over 900 lines after G-093 and G-094 | For a later goal; it was not split here |

## What held

**Undo and redo.** Sixty brush strokes: 49 steps back are offered (the cap of 50, counting the present), then no more; 49
steps forward return a file equal byte for byte to the one saved before undoing. A stroke, a half-stitch stroke, a rename,
a fabric change, a quick mirror and a crop to a piece (a change of size), undone one by one in 8 steps, return the first
file byte for byte; redone, the last file byte for byte. Regenerate keeps the chart's fabric and is undone to the chart
before it, byte for byte. No page error in any of it.

**The file.** A file saved before fabric existed opens on the browser's count and is saved again as the same bytes. A file
from a later version (9) is refused with its message and the open chart stays. A fabric that is not a count and a unit is
dropped and the chart opens on the browser's. An OXS file's count (18) becomes the chart's and is in its saved file, and
the browser's own count (11) is left alone. After a reload the chart, its fabric and its status line are back, and undo is
unavailable, as before.

**Fabric.** A new chart is given the fabric in force; a change of count or unit is one undo step and is in the saved file;
the file opened in a browser with no settings shows its own count and unit; the count chosen for an empty grid on the
start screen is the new chart's and not that of the chart being replaced.

## Coverage

**Exercised:** the above, through the interface, plus the full suite (563 cases before this pass, all passing).

**Not exercised:** a 1500 × 1500 chart in the browser (the history was measured at that size in Node,
`docs/reviews/2026-10-05-undo-and-flatten.md`; the editor itself was not profiled); any browser but the suite's Chromium;
files written by versions 1 to 6 of the app from a real archive (the unit tests build them by hand); a document of more
than one layer anywhere but the unit tests, since the editor cannot make one. The live site is checked after deploy.
