# QA, 2026-10-05 (G-099)

**Mode and scope:** scoped pass on what G-099 changed: how a generation request is checked, sent and read, and the pipeline
that makes the chart. The goal intends no change of behaviour, and what generation produces is not a matter of opinion: a
chart is the same bytes or it is not. So this pass is comparison rather than exploration. Nobody looked at charts by eye.

## What was compared

| What | How | Result |
|---|---|---|
| The charts the pipeline makes | The 74 recorded golden cases, and eight more cases hashed before and after by `scripts/measure-generation.ts` (among them traced lines with texture strokes and a chosen set of colours, which the golden cases do not cover) | All identical; checked again after the proof was added and removed |
| The processor's answer to a request | The check as it was before the goal and as it is now, run side by side over 20,112 requests: every setting varied one at a time through valid, boundary and wrong values, then 20,000 random mixtures. 21 different refusals were reached | 0 answered differently: the same request is accepted, or refused in the same words |
| Generating through the interface | The 57 browser cases that generate (every palette mode, both edge modes, dithering, Vivid, the photo sliders, traced lines, texture strokes, a set-up palette, a transparent photo) | All pass; and the whole suite, 564 cases |
| A new setting, end to end | The proof: a temporary setting drawn from its declaration, sent, checked, read by its own Rust module, kept across a reload, a wrong value refused | Worked; removed |

## Findings

| # | Severity | Finding | Outcome |
|---|---|---|---|
| 1 | test defect (new, caught before commit) | A test of mine listed a value by hand for every setting, so adding a setting broke the build until the test was edited. It contradicted the goal | Fixed: settings drawn from their declarations are taken from them. The pinned list of settings is still edited when one is added, on purpose |
| 2 | note | Rust now refuses a setting it does not read, where it used to ignore it. The processor sends only declared settings, so nothing that reaches it in production can be refused this way; a hand-made call to the binary with a stray field now fails, by name | As intended |
| 3 | note | Rust's own words for a value of the wrong kind changed (it no longer uses the JSON library's). They are never shown: the processor checks a request before the binary sees it | Left |

## Not covered

Generation at 1,500 stitches through the interface. The live site until after deploy. The wording and placement of the
"More" section a drawn setting appears under was seen once, in the proof's screenshot; it is plain and is the redesign's
to place.
