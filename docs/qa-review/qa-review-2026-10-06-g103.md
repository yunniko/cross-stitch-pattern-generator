# QA review — G-103 (the three workspaces as features), 2026-10-06

**Mode and scope:** changed, `e667b7a..a838090` plus the uncommitted fixes it led to (committed as f373200). Surfaces:
the workspace tabs Hidden and Locked, landing in the next workspace on, commands and keys, the start screen, Save,
Export-then-start-new, Continue in Edit, the all-off message, and the four server refusals. Run against a local
production build on port 30200 with `CS_JOB_BINARY` set; site states set through the test database helpers. No admin
page and nothing on the live site was touched.

## What was exercised

- Every state of each workspace's switch, by `tests/e2e/workspace-switches.spec.ts` (10 of 10 locally after the fixes),
  and by hand: tab absent or greyed with its note, landing, the "b" key and the command list's rows, Undo kept with Edit
  off, Save and Export-then-start-new greyed or absent, Continue in Edit greyed after a real generation.
- A switch changed while in use: in Edit with Rectangle in hand, Edit locked moves the person to Photo with Pan and
  keeps the chart's name; switching back gives Rectangle again. All three off and back keeps the chart.
- Server refusals with malformed JSON, an empty body, a `<script>` string and a 30 MB body: 403 by the workspace's name
  before the body is read, for all four routes. `GET /api/jobs/nope` answers 400 (not a workspace request).
- No console errors in any of the states above.

## Coverage

Not exercised: assistive-technology reading of the greyed tabs beyond their `title` and `disabled` state; contrast was
judged by eye; a drop of a non-image file was covered only by reading the handler (it takes the first `image/*` file);
the full e2e suite runs in CI, not locally (the machine lacks the memory for it).
